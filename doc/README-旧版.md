# 夢回尋仙 GM 工具：Python 还原版

这是根据 `夢回尋仙GM工具.exe` 中的 Python 3.13 字节码静态重建的可读源码，**不是原作者的原始 `.py` 文件**。原始注释、变量写法和排版无法从字节码恢复。`index.original.html`、`items.json`、`scenes.json`、`icon.ico` 是从 EXE 内嵌归档逐字节提取的资源；`index.html` 增加了网页配置界面。

## 文件

- `gm_server.py`：配置、SSH/MySQL、HTTP API 和日志，不包含系统托盘。
- `index.html`：网页控制台（玉色主题、图标侧栏、合并页子视图，CSS/JS 内联），含「操作日志 → 连接配置」。
- `index.original.html`：从 EXE 提取、未修改的网页控制台，供核对。
- `items.json`、`scenes.json`：原程序内嵌的物品和场景数据。
- `icon.ico`：原程序内嵌图标，保留作参考；无托盘版本不使用它。
- `requirements.txt`：只需安装 `paramiko`。原程序使用 Python 3.13；建议用 Python 3.13 运行此还原版。

## 运行

在隔离环境中运行 `python -m pip install -r requirements.txt`，然后运行 `python gm_server.py`。浏览器打开 `http://127.0.0.1:8899`，进入「操作日志 → 连接配置」，填写服务端实际 IP、SSH 端口、凭据与数据库信息并保存。默认 SSH 端口是 `22`；例如：

```json
"ssh_host": "192.168.1.100",
"ssh_port": 22
```

这里的 `192.168.1.100` 仅为示例；安装包没有提供实际服务端 IP。程序会把网页配置写入同目录的 `gm_config.json`。原有 `127.0.0.1:2222` 配置可直接在网页上改掉。SSH、MySQL 和数据库配置保存后立即用于后续请求；若修改网页监听地址或端口，需要重新启动程序。网页监听地址只允许本机回环 IP。建议在操作前备份目标数据库。程序会保持运行，直到关闭终端或访问原有的 `/api/quit` 接口。

密码输入框留空表示保持已有密码；读取配置时，API 只返回“是否已设置密码”，不会返回密码内容。“测试连接”会按当前已保存的设置执行连接检查。

更新程序时请覆盖原目录中的程序文件，保留同目录的 `gm_config.json`。发布用 ZIP 不包含该文件，因为其中保存了 SSH 和 MySQL 密码；若解压到新目录，需要把旧目录的 `gm_config.json` 复制到新目录后再启动。页面底部会显示当前读取的配置文件路径，密码框空白只表示密码不回显，并不代表已清除。

## 点券和物品写入校验

「游戏配置」包含倍率设置、基础定义表和动态定义表。倍率设置读写 `TTYGZS/dynamicmb/server_set.txt`；两个定义表分别读写 `TTYGZS/mb/etc/define.txt` 和 `TTYGZS/dynamicmb/define.txt`。保存会在服务器同目录创建带时间戳的备份，定义表保留原编码、编号和说明，只修改数据列。倍率保存后仍需用 GM 角色执行 `reloaddynamic 1`；定义表需按对应表 ID 执行 `reloadexcel <表ID>` 或 `reloaddynamic <表ID>`，配置才会生效。

当前服务端的购物点券通道从 `xunxian_ims_84.point_partition_0` 按账号名读取余额；`point_partition_01` 是历史副本。输入账号 ID 时，工具先从 `common_accounts` 查出账号名。新账号没有点券记录时，会在主分表里自动建一条初始余额为 0 的记录，再执行充值；更新后重新读取余额确认。`test` 账号已完成新增记录、加 1 点、扣 1 点的实际验证，最终余额仍为 0；服务端原生点券查询返回成功，余额为 0。点券值上限为 2147483647。

已在这套游戏服务端实测：角色背包实际保存在 `common_char_whstream.whstream`；仅写入 `entire_items` 和 `common_items` 后，重新登录仍不会得到道具。现在，完全下线的角色可以发放物品清单里**任意类型**的道具：程序按道具类型，从该角色背包中取一条**同类型**的现有记录作为字节模板，只改写 `SItemUnit` 里的 excel ID、唯一编号、背包位置和 `byNum` 数量，其余字段（耐久、绑定、附魔等类型专有状态）沿用同类真实道具。写入前会保存原存档备份到 `data/whstream_backups/`，写入后校验并清理读档缓存。`test01` 已在重新登录后确认“智慧仙丹”图标右下角显示 **50**，退出后数据库读回仍为 50。

为什么要同类型模板：存档里每条 `SItemUnit` 都是 140 字节定长结构，所有类型共用同一布局，但结构尾部保存的是该类型专有的状态。用消耗品的记录去改出一件武器，会得到耐久为 0 的坏装备，所以发放某类型时要求背包里已存在至少一件该类型道具。缺少模板、槽位不足、角色仍在线或存档格式不同，都会拒绝写入并给出具体原因。数量表示一个道具堆叠中的个数，背包通常只显示一个图标；装备、时装等非堆叠道具数量填 1。网页上的「检查背包」会列出该角色当前可作为模板的类型和剩余槽位。邮件正文使用游戏原生 UTF-8 文本字段，标题显示在正文首行；物品清单通过背包发放流程交付，当前不作为邮件附件。修改源码后必须重启正在运行的 Python 程序。

## 还原范围与验证

已重建主模块的 HTTP GET/POST 路由及其 SQL 生成逻辑，并按用户要求移除了系统托盘、改为直连服务端 SSH，增加了网页配置功能。`items.json`、`scenes.json`、`icon.ico` 与 `index.original.html` 直接来自原 EXE。源码已通过语法编译检查和无数据库连接的接口烟雾测试，并连接当前游戏服务端验证了部分数据库行为。没有在 Windows 上运行原 EXE，无法声明与原程序在所有环境和数据库状态下完全等价。邮件二进制格式在原界面中也被注明为尚未在游戏内验证。

原程序默认配置包含示例 SSH/MySQL 凭据，使用 SSH 自动接受主机密钥策略，HTTP API 没有鉴权；此还原版保留这些行为以反映原程序。不要将监听地址改为公网地址。
