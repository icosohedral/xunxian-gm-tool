# 签系召唤物同步施法测试

> 当前汇总请参阅 [签系修改当前配置与验证](签系修改当前配置与验证.md)；本文保留专题和历史测试记录。

## 目标

玩家装备指定效果后释放九星，自己的签兵、签将、签王分别对各自当前目标同步施放九星；后续可扩展至其他技能。本次先以挂机神剑 `60074` 为测试载体。

## 首次测试实现（已替换）

2026-11-01 已在普通线和交易线加载进程内测试模块，源码为 `scripts/native/summon_mirror_skill_test.c`。玩家通过 `CServerCha::UseSkill` 开始第一个技能动作时，代码先保留原有 `ProcessFirstSkillMethod` 行为；当技能 ID 为 `3002`、施法者为玩家、装备武器 ID 为 `60074` 时，遍历该玩家的召唤物列表，筛选召唤类型 `20、21、22、349、350、351、355、361`。

对于有有效当前目标的召唤物，向其发送九星施法任务，目标为它自己的当前目标 ID；没有当前目标时跳过。仅检查玩家施法者，召唤物自己的施法不会再次触发同步。技能 ID 和召唤类型目前写在测试代码中，后续要扩展技能需要修改代码。

当前为**按武器 ID 判断的临时测试**，不是独立的可配置装备状态或词条。未修改装备配置、技能表或客户端包，也未设置技能说明。签系召唤物是否能通过九星的任务与技能限制、正确播放动作和飞行物并产生伤害，尚未在游戏内验证。召唤物正在执行其他动作、目标超出范围或失效等情况，可能由原有任务系统拒绝或改变行为。

首次测试模块在 `TTYGZS_d.so` 的 `0x928c3b` 调用点挂接，仅适用于 SHA-256 为 `9a19e9c8deaefeb8ba35d61f10ccc6f32d166ef2ee2aedf1f3ecf06cfa7109bb` 的已核对版本；安装前检查原指令和线路进程，安装后两条线路调用点回读均指向新模块。原来的百分比伤害及吸血钩子在另外两个调用点，回读仍指向原运行模块。本次只修改进程内存，服务端重启后消失。

## 游戏内验证

1. 装备挂机神剑，召唤签兵、签将或签王，让召唤物先拥有自己的有效目标；角色施放九星，观察每个召唤物是否对各自目标施放，并核对动作、飞行物和伤害。
2. 召唤物没有目标、目标死亡或超距时观察是否按预期跳过或被施法系统拒绝；检查正在释放其他技能时的行为。
3. 卸下武器后重复施放，确认不再同步；核对原有最大生命百分比伤害、吸血和其他召唤物行为。
4. 如同步无效，追踪召唤物施法任务的拒绝原因，核对九星玩家技能的装备、职业、技能等级、AI 和客户端动画要求；必要时复制为召唤物专用技能并建立独立装备状态，再进行测试。

## 首次测试反馈与调整

用户反馈第一版召唤物没有九星特效和伤害。静态检查发现 `CServerChaNPC::SetCurTask` 对技能任务存在 NPC 自身技能列表检查；九星 `3002` 是玩家技能，因此该检查是可能的拦截点，但首次版本没有计数数据，不能确认它就是唯一原因。

测试版第二次调整为使用 `CServerCha::SetCurTask` 基类入口提交九星任务，绕开该 NPC 入口的技能列表检查，后续技能条件及执行过程仍由游戏引擎处理。模块增加只读计数器，分别记录玩家施法、武器匹配、召唤物列表、类型、目标和任务接受/拒绝次数。两条线路已更新并回读确认调用点，普通线观测到 3 次签将任务入口返回接受；这不能证明实际施法、动画或伤害成功，仍需游戏内反馈。

## 客户端与服务端事件拆分

用户反馈单段 NPC 技能仍没有飞行物和伤害。运行时读取证实，技能组 `60000`、技能段 `990001`、触发事件 `9900001` 及飞行子物体 `60000` 的表项均已加载，但诊断发现技能段的服务端事件数组为空。

逆向 `CMethodDataMng::LoadExcel` 发现，触发类型 `30010` 会归入客户端事件，服务端不会将其加入技能段事件数组。原 NPC 投射技能的动作除 `30010` 外还包含 `20018` 服务端事件；此前复制时只保留了视觉事件。当前补充触发事件 `9900002`（复制同 NPC 模板事件 `1000391`，类型 `20018`），技能段事件数组改为 `9900001*9900002`；两个事件时间均为 `0`。是否实际产生目标伤害及飞行物，仍需用户重新启动客户端后验证，不能仅凭表加载或任务进入就认定成功。

本次更新分别合并到最新客户端、服务端主包和动态包，未保留额外 DPK 备份；两条线路技能表重载成功，客户端游戏目录 `mb.dpk` 已同步更新。
