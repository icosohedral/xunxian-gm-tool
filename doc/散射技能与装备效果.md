# 散射技能与装备效果

## 穿透敌人：实现方向

以下为部署前的静态分析；当前状态见文末的游戏内验证记录。客户端工作包和服务端主包中，散射技能 3048 的普通飞剑子物体为 809、暴击飞剑为 1190；散射 3094 的普通飞剑为 6680，暴击分支引用 1190。三者在 `skill/methodunit_data.txt` 或 `skill/methodunit_data1.txt` 中的“打中目标消失”均为 1，飞行模式均为 2。服务器动态包同样包含 809、1190；各包具体生效来源需在实施时核实。

运行服务端 `TTYGZS_d.so` SHA-256 为 `9a19e9c8deaefeb8ba35d61f10ccc6f32d166ef2ee2aedf1f3ecf06cfa7109bb`。其 `CFlyUnitS::Hit(CCha*)`（0xa7942c）先调用普通子物体命中处理；成功后读取配置第 11 列（从 0 开始，即“打中目标消失”），值大于 0 且满足另一对象标识比较时，调用 `CMethodBase::EndTrigger(3)` 并执行虚函数。0 值绕过该结束分支。条件比较的确切含义及虚函数行为仍须进一步确认，不能仅凭字段名称断言所有碰撞都会终止。

同表存在飞行模式 2、命中消失为 0 的其他飞行物，说明该组合在配置中存在，但不能据此证明散射一定能穿透并重复对不同敌人造成伤害。建议优先在隔离测试中复制散射子物体与对应动作、触发配置，将复制记录的命中消失设为 0；使用独立技能先验证正常和暴击分支是否连续命中不同敌人、单支飞剑是否会重复命中同一目标、飞行时间到期和到达目标点后的清理以及客户端视觉。直接修改 809、1190、6680 将影响所有引用它们的技能，不能满足仅装备指定物品时生效。

若复制配置证明可用，再研究在服务器创建飞剑时按施法者装备选择原版或穿透版配置，以及对应客户端显示同步；装备判断、特殊分支和客户端按装备选择子物体的能力尚未验证。若 0 值只是延长显示而无多目标伤害，需要继续追踪 `CMethodUnit::Hit`、碰撞检测及触发器的目标去重逻辑，再设计针对特定装备和散射飞剑的处理。任何调用点改动须校验二进制版本和既有钩子，并纳入自动恢复。

## 2026-11-03 回滚

测试钩子安装后，普通线进程退出码 139，服务整体停止；时间上与测试钩子相近，暂不能仅凭退出码确定原因。已恢复部署前的自动恢复脚本，不再自动加载散射钩子；此前“已部署”仅为历史状态。实验源码不得重新部署，须先分析崩溃并完成隔离验证。

## 崩溃原因（已定位）

2026-11-03 19:59 普通线记录 SIGSEGV。崩溃指令地址相对游戏模块为 `0x6559b0`，即 `SExcelLine::SafeGetInt` 的 PLT 跳板；现场 EBX 为 1。i386 的该跳板以 EBX 为游戏模块 GOT 基址寻址，不能把它作为普通独立函数地址直接从编译器生成的 C 代码调用。实验模块在第一次读取后把返回值 1 放入 EBX，然后再次进入该 PLT 跳板，从错误地址间接取函数指针而崩溃。栈顶返回地址对应实验模块中第二次调用返回处，确认来源。该全局命中入口先读取配置后才检查武器，因此符合条件的其他飞剑也可能触发崩溃。

隔离测试只覆盖了原型条件判断，没有覆盖真实 PLT 调用及 EBX 约定，是部署前验证不足。当时曾加入编译阻断并停用；后续修复与重新启用情况见下一节。

2026-11-03 游戏反馈没有穿透；普通线外层钩子计数显示 22 次符合条件的 809 飞剑，因此武器判断至少已在命中时触发。进一步反汇编发现 `CMethodUnit::Hit` 在外层 `CFlyUnitS::Hit` 之前也读取命中消失字段，并可调用结束处理；此前只修改外层读取，不足以覆盖内部处理。

## 再次反馈未看到穿透

2026-11-03 复查运行计数：普通线内部读取点累计 28 次、外层读取点累计 65 次符合 60079 条件，最近飞剑均为 809；计数只说明钩子被触发，不能证明两个不同怪物都受伤，也不能区分客户端视觉。飞剑配置还设有“到达目标点消失”列 22 为 1。`CFlyUnitS::Logic` 在 `FlyUnitCtrl::IsArrive` 为真时读取该列并可触发结束；`FlyUnitCtrl::MoveStep` 到达终点后把位置设为终点并标记到达。由此可知单纯跳过命中消失不足以证明飞剑会越过当前行程终点；关闭到达消失亦不代表会继续运动。实际终点是否为首个怪物位置、碰撞是否继续、后方怪物是否掉血及客户端呈现仍待实测，尚未据此再次修改游戏。

## 散射命中人数限制

2026-11-03 用户确认后方怪物没有掉血。服务端 `CMethodBase::GetMayHit` 在 `0xb1c859` 读取动作表第 11 列“攻击人数”，对新目标按已命中目标数检查上限；散射动作 30079、30143、30275、30276 的该列均为 1。该限制独立于命中消失，是阻止后续目标的一项明确限制；不能因此断言它是唯一限制。
