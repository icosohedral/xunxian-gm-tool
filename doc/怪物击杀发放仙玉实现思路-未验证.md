# 怪物击杀发放仙玉实现思路

## 目标

指定怪物死亡后，直接向最先攻击该怪物的角色所属账号增加仙玉（点券），与游戏原有怪物奖励归属保持一致，不生成需要拾取的掉落物。使用游戏进程内的死亡钩子及游戏已有的点券接口，不额外部署奖励服务。

本文是实现方案和调查记录，尚未实现或完成游戏内验证。

## 已确认的服务端线索

当前测试服务器的 `TTYGZS_d.so` SHA-256 为 `9a19e9c8deaefeb8ba35d61f10ccc6f32d166ef2ee2aedf1f3ecf06cfa7109bb`。不同版本的地址、对象布局和调用方式不可直接照搬。

- `CServerChaNPC::SetDead(int)`：NPC 死亡处理函数。反汇编显示该函数内部调用 `CServerCha::GetFirstAttackPlayer()` 和 `CServerCha::GetLastAttackPlayer()`。奖励归属应优先研究前者，后者是最后攻击玩家，不适合直接作为本功能的奖励对象。
- `CServerCha::GetFirstAttackPlayer()`：从函数名及死亡处理中的调用看，是获取最先攻击玩家的候选接口；返回对象和有效期仍需运行时验证。
- 玩家数据管理对象有 `GetGID()`、`GetAccountID()`、`GetAccountName()` 和 `GetName()` 等符号；实际返回值与角色 ID、账号的对应关系仍需运行时验证。
- `CPlayerDataMngS::AddPayBackPoint(int, int, int, bool)`：此前分析显示，仙玉凭证的使用效果会调用该接口并发起点券增加请求。参数含义及其他调用场景的请求格式尚需验证。

## 预期流程

```text
怪物确认死亡
  → 取得怪物配置 ID
  → 根据奖励规则判断是否发奖及奖励数量
  → 取得最先攻击玩家的数据对象
  → 调用 AddPayBackPoint 发起点券增加请求
  → 点券代理处理请求并更新账号余额
  → 保留游戏原有死亡、经验和掉落处理
```

### 1. 加载扩展与挂钩

为当前 Linux 服务端构建匹配架构和核心版本的原生扩展，在游戏进程启动时加载。扩展在 `CServerChaNPC::SetDead(int)` 的有效死亡处理路径设置钩子，并保留原始函数行为。

实际挂钩位置、函数调用约定、参数、寄存器与原指令恢复方式必须通过反汇编和运行时验证。`SetDead` 包含多个分支，不能在入口无条件发奖；也不能假定原函数执行后对象和攻击者信息仍然有效。版本校验失败时不加载钩子。

### 2. 取得首攻角色和怪物

在确认有效死亡的时机，读取怪物配置 ID，优先验证并使用 `GetFirstAttackPlayer()` 取得玩家对象；结果为空时记录并跳过，不能自动改发给最后攻击者。核对角色 ID 和账号信息，日志优先记录角色 ID。

首攻归属在普通攻击、宠物、持续伤害及组队等场景下如何确定，需要与游戏原有奖励规则对照测试。不能仅凭函数名认定这些场景的归属，也需要确认首攻玩家离线时的处理方式。

### 3. 计算奖励

按怪物配置 ID 查询规则。第一版可用固定数量，确认流程稳定后再考虑概率与随机范围。未配置的怪物不发奖；无效或超出范围的奖励数值应拒绝。

### 4. 发放和记录

通过玩家数据对象调用 `AddPayBackPoint(...)`，沿用已有的游戏点券请求和服务端代理，不直接从游戏主线程修改数据库。

在实现前核实接口四个参数的意义、余额单位、请求是否被当前代理接受，以及成功或失败如何反馈。记录怪物 ID、角色 ID、账号、奖励数量、发放状态及时间，便于排查。

### 5. 重复和失败处理

同一怪物的死亡处理可能重复进入；需以怪物实例和本次死亡状态为基础防止重复发奖，而不是仅用怪物配置 ID 和角色 ID 去重。实例 ID、重生后如何区分新一次死亡以及重启后的唯一性需要实测后确定。

直接调用方案较简单，但如果没有持久化事件或可靠回执，进程退出或点券请求失败时可能漏发，也无法保证重试不重复。先明确第一版的失败记录与补发策略，确认需要可靠自动重试时再设计持久化机制。

## 实施与验证顺序

1. 只读追踪有效死亡分支，确认怪物 ID、玩家对象和角色 ID 的取得方式。
2. 编写仅记录击杀事件的钩子，验证死亡时机和首攻角色归属，不发点券。
3. 测试普通击杀、组队、宠物、持续伤害、无玩家击杀、怪物删除与重生，并检查重复事件。
4. 分析和验证 `AddPayBackPoint` 参数及点券代理请求；以少量固定仙玉测试实际入账和失败记录。
5. 接入怪物奖励配置，测试未配置怪物、重复死亡、进程重启和请求失败。
6. 部署前备份并校验核心版本；扩展异常时能够关闭或回滚，原游戏死亡逻辑继续正常执行。
