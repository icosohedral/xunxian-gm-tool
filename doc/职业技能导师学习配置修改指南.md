# 职业技能导师学习配置修改指南

本文以“寻梦”客户端与服务端的 `mb.dpk` 为例，说明如何让已有技能出现在职业导师处并允许学习。本文记录的是资源表修改方法；技能能否在游戏里正常施放，还需要实际登录验证。

## 一、先确认技能数据

不要仅凭技能名称修改。先在客户端和服务端各自的 `mb.dpk` 中确认技能 ID、数据表和方法链。可用本项目的解包工具：

```bash
python3 unpack.py /path/to/mb.dpk -o /path/to/mb_unpacked
```

本次实例：

| 技能 ID | 包内名称 | 技能定义 | 已有方法 | 修改前的主要缺口 |
| --- | --- | --- | --- | --- |
| 3027 | 遁甲术·巨甲遁 | `skill/skill_data_yx.txt` | `30140*30086*30087` | 缺学习记录 |
| 3028 | 遁甲术·缩地术 | `skill/skill_data_yx.txt` | `30089` | 缺学习记录和游侠导师列表项 |
| 3032 | 遁甲术·解缚遁 | `skill/skill_data_yx.txt` | `30099*30101` | 缺学习记录 |
| 4022 | 葫芦收人 | `skill/skill_data_fs.txt` | `40032*40033*40034` | 缺学习记录、游侠导师列表项和游侠技能集项 |

“葫芦收人术”在这套包里的实际名称为“葫芦收人”，ID 为 `4022`。它定义在法师技能表中，允许奇门学习属于跨职业配置，尤其需要验证施放行为。

## 二、决定需要修改哪些表

| 包内资源 | 作用 | 修改规则 |
| --- | --- | --- |
| `skill/skill_data_yx.txt` / `skill/skill_data_fs.txt` | 技能定义、方法 ID、图标等 | 已有技能定义时通常不改；先检查方法链确实存在。 |
| `skill/skill_learn.txt` | 是否可学、最高等级、职业、费用、等级要求等 | 每个要开放学习的技能 ID 都需要对应学习行。 |
| `skill/npc_teach_skill.txt` | 职业导师提供的技能 ID | 目标 ID 必须出现在相应导师的第 4 列 `*` 分隔列表中。 |
| `skill/skill_cha_yx.txt` | 游侠技能集 | 奇门技能 ID 必须在“游侠”行的第 4 列列表中；跨职业技能尤其要检查。 |
| `skill/method_data_*.txt`、`skill/trigger_*.txt` | 技能执行链 | 用于判断是否有实现数据；开放学习本身不替代执行链。 |

在这套包中，“游侠导师”同时服务驭剑与奇门；真正的职业限制还要看 `skill_learn.txt` 中的职业 ID。奇门游侠为 `4`，控火法师为 `5`。只把 ID 加进导师列表，不能代替学习记录。

## 三、添加学习记录

`skill/skill_learn.txt` 为 GB18030 编码、制表符分列。对本次单级技能，可以复制同职业现有的 `3026 遁甲术·木桩遁` **整行**作为模板，再修改指定字段：

| 列（从 1 开始） | 内容 | 本次设置 |
| --- | --- | --- |
| 1 | 技能名称 | 对应的包内名称 |
| 2 | 技能 ID | `3027`、`3028`、`3032` 或 `4022` |
| 3 | 学习开关 | `1` |
| 4 | 最高技能等级 | `1` |
| 5 | 职业 ID | `4`（奇门游侠） |
| 6 | 学习费用 | `1` |
| 7 | 角色等级要求 | `30` |

其余列沿用模板，不要删除空列或末尾制表符。这次实际写入的模板有 35 列；第 12 列沿用模板值 `80`。修改其他版本时，应以该版本自己的现有同行为模板，不能直接覆盖整份学习表。

如果想改变学习等级或费用，只改第 7、第 6 列，并在客户端、服务端保持一致。写入前检查目标 ID 是否已经存在，避免重复行。

## 四、补导师列表和技能集

在 `skill/npc_teach_skill.txt` 的“游侠导师”行，第 4 列为 `*` 分隔的技能 ID。本次补入 `3028`、`4022`；`3027`、`3032` 原本已在列表中。

在 `skill/skill_cha_yx.txt` 的“游侠”行（角色 ID `1003`），第 4 列也是 `*` 分隔的技能 ID。本次只需补入 `4022`；另外三个 ID 原本已在技能集中。

新增时检查 ID 只出现一次，并保持原有的制表符、换行和其他字段。不要把 `4022` 从法师技能表或法师技能集中移走。

## 五、客户端与服务端分别打包

客户端和服务端的 `mb.dpk` 不是同一份文件；资源总数和表内容也不同。**分别从各自原包解出资源、修改、重新封包**。不要把客户端的整份 `skill_learn.txt` 复制到服务端，反之亦然。

寻梦服务端还存在 `dynamicmb/mb.dpk`。该包也含有 `skill_learn.txt`、`npc_teach_skill.txt`、`skill_cha_yx.txt`；只修改服务端主包后，动态包仍可能提供旧配置。部署前应逐一检查主包和动态包，分别用各自的原表制作补丁并备份。动态包的学习表列数与主包不同，不能直接复制主包的整行或整个资源文件。

本项目 `repack.py` 每次替换一个包内资源，并输出新 DPK，不直接覆盖输入。需要改三个资源时，以上一步的输出作为下一步输入：

```bash
python3 repack.py mb.dpk skill/skill_learn.txt ./edited/skill_learn.txt -o mb.step1.dpk
python3 repack.py mb.step1.dpk skill/npc_teach_skill.txt ./edited/npc_teach_skill.txt -o mb.step2.dpk
python3 repack.py mb.step2.dpk skill/skill_cha_yx.txt ./edited/skill_cha_yx.txt -o mb.new.dpk
```

命令中的 `./edited` 是示例目录。改动较少时仍应保留整个资源文件的编码和列结构。`repack.py` 会执行资源深度校验；确认成功后，再核对新包内的学习行、导师列表、技能集和 SHA-256。

## 六、备份、部署和验证

1. 分别备份客户端、服务端主包和服务端动态包的旧 `mb.dpk`，记录 SHA-256。服务端还要确认实际运行目录及文件属主、权限。
2. 将已校验的新包上传到服务端同目录的临时文件，核对上传前后的 SHA-256，再保留原属主和权限并替换主包。
3. 按服务器的停服流程重启服务，让它重新加载资源。若脚本要求确认所有客户端正常退出，应先满足这一条件。修改文件本身不会让正在运行的进程自动重新加载技能表。
4. 用符合等级条件的奇门角色检查导师界面是否显示三个新增技能，分别点击学习；然后检查技能栏、技能等级、费用扣除及实际施放。`4022` 还要重点检查奇门角色能否使用法师表中的方法链。
5. 如果导师不显示技能，依次核对客户端、服务端主包、服务端动态包的学习记录、导师列表、游侠技能集是否都包含该 ID，并检查职业 ID、等级要求和重复行。

回滚时，先按同样的停服流程，将各自备份的 `mb.dpk` 恢复到原位置，核对哈希、属主和权限，再重启。不要用客户端备份恢复服务端，或用服务端备份恢复客户端。
