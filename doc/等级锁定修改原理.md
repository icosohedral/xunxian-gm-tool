# 等级锁定修改原理

## 功能作用

工作台「游戏配置 → 等级锁定」用于管理天劫等级锁。列表左侧显示劫名和等级（风云劫·40级、天雷劫·60级、十方劫·80级、魂魄劫·98级、五行劫·100级），右侧开关表示该等级锁是否启用。关闭开关会把该等级对应的锁值设为 `200`；重新开启时，程序按原始 `mb.dpk` 中该等级对应的配置行编号恢复锁值。程序只修改 `fate_info.txt` 有效配置行的第 3 列「等级锁」，其他列、表头和注释行保持原样。

切换开关只暂存在页面中；点击卡片下方的「保存修改」后，所有待修改等级会一起写入，并生成一份备份。

单独修改时，关闭开关按第 3 列当前的锁值匹配。例如关闭 40 级开关，只把第 3 列当前值为 `40` 的配置行改为 `200`，其他锁值（如 `60`、`80`）保持不变。开启开关时，程序从原始 `mb.dpk` 找出该等级对应的配置行编号，只恢复这些行，其他配置不变。一个等级锁值可能对应多条配置行，这些行会一起修改；页面不展示行数。

## 配置文件与读取顺序

服务端路径：

```text
/opt/xxserver/runtime/xx/shm/TTYGZS/mb/quest/fate_info.txt
```

程序读取时优先检查这个松散覆盖文件。如果文件不存在，则从以下数据包中的 `quest/fate_info.txt` 读取原表：

```text
/opt/xxserver/runtime/xx/shm/TTYGZS/mb.dpk
```

因此首次应用时不需要手动解包或预先创建 `quest` 目录。程序会以修改后的松散覆盖文件覆盖数据包中的同名表。

为避免反复下载较大的 `mb.dpk`，工作台会把提取出的原表缓存在本机 `data/fate_info_package_cache.json`。读取时先通过 SSH 检查数据包的大小和修改时间；没有变化就复用缓存，发生变化才重新下载并提取。工作台运行期间也会使用内存缓存。

## 写入与校验

1. 通过工作台已配置的 SSH 连接读取当前生效的表。
2. 识别有数字索引的配置行，只改所选等级对应配置行的第 3 列；关闭时设为 `200`，开启时恢复原始锁值。
3. 在写入前于原文件旁创建带时间戳的备份，文件名类似 `fate_info.txt.bak.20261022-120000-123456789`。
4. 首次创建覆盖文件时，备份内容取自 `mb.dpk` 中的原表；之后修改已存在的覆盖文件时，备份该覆盖文件。
5. 写入临时文件后再原子替换目标文件，并重新读取检查：确认目标等级的锁值符合开关状态，其他等级锁值保持不变。校验不通过会报告错误。

远程写入使用非交互式 `sudo`。因此 SSH 用户需要有权通过 `sudo -n` 读取和写入该配置路径。程序不会在读取表格或切换开关时修改服务端文件；只有点击「保存修改」才会写入。

## 生效方式

修改文件后需要重启游戏服务端，新的等级锁配置才会被加载。工作台保存成功只代表文件写入并通过回读校验，不代表游戏进程已经重启。

## 回滚

若首次应用时此前没有松散覆盖文件，删除该覆盖文件并重启，服务端会重新使用 `mb.dpk` 中的原表：

```bash
sudo rm -- /opt/xxserver/runtime/xx/shm/TTYGZS/mb/quest/fate_info.txt
```

如果应用前已经存在松散覆盖文件，应使用对应的时间戳备份恢复，而不是删除文件：

```bash
sudo cp -p /opt/xxserver/runtime/xx/shm/TTYGZS/mb/quest/fate_info.txt.bak.时间戳 \
  /opt/xxserver/runtime/xx/shm/TTYGZS/mb/quest/fate_info.txt
```

恢复或删除后都需要重启游戏服务端。执行回滚前应先确认备份文件对应的是本次操作前的版本。

## 注意

- 本功能修改的是 `fate_info.txt` 第 3 列，不会删除或改写天劫任务本身。
- 修改把等级锁值统一设为 `200`；它解除低等级锁的阻断，但角色等级仍受游戏其他等级上限和规则影响。
- 如果服务端配置路径或 DPK 位置与上面不同，需要先调整工作台服务端路径配置后再使用。
