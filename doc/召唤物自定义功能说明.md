# 自定义召唤物功能说明

本文记录工作台「技能配置 → 召唤物」的实现方式、包修改内容、部署流程和已知边界，方便后续维护和排查。

## 功能概述

在工作台选择一个召唤物外形，为其配置一项自定义召唤技能，并从该召唤物对应的技能中选择最多 5 项放入召唤物自己的技能栏。召唤技能名称、召唤冷却和每个召唤物技能的冷却都可以配置。

召唤物资料来自 `doc/召唤物列表.csv`。列表按角色名称和完整技能列表合并重复项；同一个外形或技能若被多个召唤物共用，界面会在应用前提示影响范围。

默认召唤技能说明为“召唤出{召唤物名称}，协助你战斗，持续十分钟”。召唤技能冷却和召唤物技能冷却范围为 1 至 3600 秒；最多选择 5 项召唤物技能。

## 技能模板与独立标识

当前实现的模板分工如下：

| 用途 | 配置来源 / ID | 说明 |
| --- | --- | --- |
| 技能逻辑、学习记录和升级数据 | 六合签，技能 ID `3046` | 自定义召唤技能的基础模板 |
| 图标 | 巨甲遁，技能 ID `3027` | 只取图标字段；界面注释标为图标 `241` |
| 新召唤技能 | 技能 ID `3126` | 与巨甲遁、六合签分开，避免直接共用技能定义和冷却 |
| 召唤触发 | 六合签触发 `300498`，复制为 `302247` | 使用新触发 ID，并按 CSV 中所选召唤物角色写入角色 ID |
| 动作方法 | 六合签动作 `30174`、`30173`、`30063` | 分别复制到新方法 ID `30422`、`30423`、`30424` |

这样处理是为了保留六合签的召唤行为，同时避免把六合签本身替换成自定义召唤物，也避免巨甲遁和自定义技能共用触发或冷却。巨甲遁只作为图标来源。

## 包内修改内容

点击「应用召唤配置」后，服务端会按同一份配置处理客户端包、服务器主包和服务器动态包。

主要修改以下配置：

- `skill/skill_data_yx.txt`：生成或更新技能 ID `3126`，以六合签技能行为字段为基础，写入自定义名称、冷却和说明，并使用巨甲遁图标。
- `skill/method_data_yx.txt`：复制六合签的动作方法并分配独立方法 ID。
- `skill/trigger_yx.txt`：复制六合签召唤触发，分配独立触发 ID，并绑定所选召唤物角色。
- `skill/skill_learn.txt`、`skill/skill_levelup.txt`：以六合签记录为模板，生成自定义技能的学习和升级记录。
- `skill/npc_teach_skill.txt`、`skill/skill_cha_yx.txt`：将新技能加入游侠导师和游侠技能清单。
- `object/cha_skill_choose.txt`：为所选召唤物外形配置被选中的技能。
- `summon/summon_skill.txt`、`summon/summon_skill_index.txt`：配置召唤物自身技能栏，使所选技能显示在召唤物技能窗口。
- `skill/skill_data_npc/*.txt`：修改所选召唤物技能的冷却时间。技能 ID 若被多个召唤物共用，冷却修改会同步影响共用者。

补丁会检查目标 ID 是否重复、动作 ID 是否被占用、所选技能是否属于该召唤物，以及资源是否存在；完成打包后会重新读取并校验所有被修改的资源。

## 应用与生效流程

1. 在「运维管理 → 连接配置」设置并保存本机客户端 `mb.dpk` 路径。
2. 进入「工作台 → 技能配置 → 召唤物」，选择召唤物、技能名称、召唤冷却和最多 5 项召唤物技能及各自冷却。
3. 点击「应用召唤配置」并确认。服务端读取客户端包及服务器当前主包、动态包，分别生成修改后的包。
4. 服务端主包和动态包自动备份后替换；替换后会核对服务器文件 SHA-256。
5. 修改后的客户端包会下载到本机，需要手动替换游戏目录中的客户端 `mb.dpk`。
6. 重启游戏服务端和客户端后验证。工具不会自动重启服务端；服务端进程运行期间虽然会写入包文件，但进程已加载的配置通常需要重启后才会重新读取。

服务器备份文件名带有 `.bak.summon.<时间戳>` 后缀。客户端包由工具下载，不会自动覆盖本机文件，替换前应自行保留原客户端包。

## 数据保存

最近一次的界面选择保存在运行目录 `data/summon_skill_config.json`，用于下次打开页面时恢复召唤物、技能名称、召唤冷却和技能冷却配置。该文件属于运行数据，不纳入 Git。

## 已知边界与排查提示

- 召唤物技能栏由所选外形对应的 `cha_skill_choose.txt` 行决定；若多个角色共用同一外形，配置会影响这些共用者。
- NPC 技能数据按技能 ID 修改。多个召唤物若共用相同技能 ID，冷却设置也会共用，应用窗口会提示。
- 当前功能只配置召唤外形、技能行为和技能栏，没有实现召唤物继承玩家属性；召唤物属性仍由服务端对应角色/外形的数据决定。
- 新技能的学习和技能栏记录写入 DPK；实际能否在游戏中学习，还取决于客户端使用了下载后的包、服务端包已替换，以及游戏内技能导师/技能配置是否重新加载。
- 代码通过复制六合签触发记录来继承召唤行为；召唤持续时间来自该模板的触发配置，技能说明文字也写入“持续十分钟”。当前实现没有单独设置一个数值型的“600 秒存在时间”字段。
- 代码没有显式清空一个名为“非战斗状态不可使用”的独立字段。当前版本改为使用六合签触发模板，避免继承巨甲遁原触发；若游戏内仍提示战斗状态限制，应检查六合签触发模板自身的条件字段并在实机验证。
- 若出现召唤出错误外形、旧召唤物或冷却互相影响，优先核对客户端和服务器是否使用同一轮生成的包，并确认新技能 ID `3126`、触发 ID `302247` 和动作 ID `30422` 至 `30424` 没有被其他配置覆盖。

## 回滚

服务端主包和动态包可用本次操作生成的 `.bak.summon.<时间戳>` 备份恢复。客户端需恢复替换前自行保存的原始 `mb.dpk`。恢复后重启服务端和客户端。
