# 自定义召唤物功能说明

本文记录工作台「技能配置 → 召唤物」的实现方式、包修改内容、部署流程和已知边界，方便后续维护和排查。

## 功能概述

在工作台选择一个召唤物外形，为其配置一项自定义召唤技能，并从该召唤物对应的技能中选择最多 4 项放入召唤物自己的技能栏。职业导师、怪物和捕快目前都使用相同的自选流程。召唤技能名称固定为“召唤伙伴”，冷却固定为 10 秒；每个召唤物技能的冷却可以单独配置。

怪物列表保留 `doc/召唤物列表.csv` 中已整理的技能，并从配置的客户端 `mb.dpk` 补充角色：以 `object/cha_fight.txt` 的战斗能力 ID 反查 `object/cha_list.txt`，只收录 AI 组为 3、且 `object/cha_skill_choose.txt` 能对应到 `skill/skill_data_npc*.txt` 技能定义的角色。无技能、测试、废弃和纯场景对象不加入。名称和技能 ID 相同的角色合并；新增合并项默认选总生命最高的角色作为召唤主体，原 CSV 已选定的主体保持原样。同一个外形或技能若被多个召唤物共用，界面会在应用前提示影响范围。

选择怪物后，属性栏显示客户端包中 `cha_list.txt` 的角色等级，以及该角色引用的 `cha_fight.txt` 战斗配置中的生命值、伤害值、法术效果、防御力和法术抗性。选择仙友导师真身后，属性栏以其 `cha_list.txt` 的战斗能力 ID 对应 `cha_shadow/cha_shadow_chafight.txt` 中 68～77 的十条高数值记录，显示该表的等级和总属性；服务器主包中的对应记录与客户端一致，动态包不包含这张表。上述值是包内配置值，游戏运行时仍可能施加其他变化，不能当作实测最终值。

默认召唤技能说明为“召唤出{召唤物名称}，协助你战斗，持续十分钟”。召唤技能冷却固定为 10 秒；召唤物技能冷却范围为 0 至 3600 秒，最多选择 4 项。

## 技能模板与独立标识

当前实现的模板分工如下：

| 用途 | 配置来源 / ID | 说明 |
| --- | --- | --- |
| 技能逻辑、学习记录和升级数据 | 六合签，技能 ID `3046` | 自定义召唤技能的基础模板 |
| 图标 | 巨甲遁，技能 ID `3027` | 只取图标字段；界面注释标为图标 `241` |
| 新召唤技能 | 技能 ID `3126` | 与巨甲遁、六合签分开，避免直接共用技能定义和冷却 |
| 召唤触发 | 六合签触发 `300498`，复制为 `302247` | 使用新触发 ID，并按 CSV 中所选召唤物角色写入角色 ID |
| 动作方法 | 六合签动作 `30174`、`30173`、`30063` | 分别复制到新方法 ID `30422`、`30423`、`30424` |

这样处理是为了保留六合签的召唤行为，同时避免把六合签本身替换成自定义召唤物，也避免巨甲遁和自定义技能共用触发或冷却。巨甲遁只作为图标来源。

## 包内修改内容

点击「应用召唤配置」后，服务端会按同一份配置处理客户端包、服务器主包和服务器动态包。

主要修改以下配置：

- `skill/skill_data_yx.txt`：生成或更新技能 ID `3126`，以六合签技能行为字段为基础，写入自定义名称、冷却和说明，并使用巨甲遁图标。
- `skill/method_data_yx.txt`：复制六合签的动作方法并分配独立方法 ID；将召唤技能专用方法的法力消耗字段（索引 39）设为 `0`。
- `skill/trigger_yx.txt`：复制六合签召唤触发，分配独立触发 ID，并绑定所选召唤物角色。
- `skill/skill_learn.txt`、`skill/skill_levelup.txt`：以六合签记录为模板，生成自定义技能的学习和升级记录；升级表中技能 `3126` 的 1 级法力消耗字段（索引 11）设为 `0`。
- `skill/npc_teach_skill.txt`、`skill/skill_cha_yx.txt`：将新技能加入游侠导师和游侠技能清单。
- `object/cha_skill_choose.txt`：按所选外形重写技能选择项，使游戏侧将所选技能作为召唤物可用技能。
- `summon/summon_skill.txt`、`summon/summon_skill_index.txt`：配置召唤物自身技能栏，使所选技能显示在召唤物技能窗口。
- `skill/skill_data_npc/*.txt`：修改所选召唤物技能的冷却时间。技能 ID 若被多个召唤物共用，冷却修改会同步影响共用者。

怪物和捕快也会重写其外形对应的 `cha_skill_choose.txt` 行。该行可能包含怪物原有的条件、权重和技能组；应用自选技能会覆盖这些字段，因此会改变原 NPC 的技能 AI。若要保留怪物原生 AI，需要另行实现 AI 条件与召唤物技能栏的映射，目前功能尚未支持。

补丁会检查目标 ID 是否重复、动作 ID 是否被占用、所选技能是否属于该召唤物，以及资源是否存在；完成打包后会重新读取并校验所有被修改的资源。

### 召唤伙伴无消耗

原六合签模板在技能升级表中配置了 `200` 法力，召唤动作 `30424` 还带有法力消耗引用 `-20001`。仅把升级表中的消耗改为 `0` 后，游戏仍出现过“所需法力不足”，因此当前生成逻辑同时将技能 `3126` 的升级表法力消耗和其专用动作 `30422`、`30423`、`30424` 的法力消耗字段设为 `0`。修改限于召唤伙伴的记录，不修改六合签原记录。

2026-10-30 已更新客户端工作包和服务端主包并成功热重载技能定义；动态包没有这些专用动作行，其已有升级记录的法力消耗已设为 `0`。这次补充动作字段后，仍需替换客户端包、完全退出并重启游戏，再验证实际施放和法力变化；目前尚未确认游戏内测试结果。

## 应用与生效流程

1. 在「运维管理 → 连接配置」设置并保存本机客户端 `mb.dpk` 路径。
2. 进入「工作台 → 技能配置 → 召唤物」，选择召唤物和最多 4 项召唤物技能及各自冷却。
3. 点击「应用召唤配置」并确认。服务端读取客户端包及服务器当前主包、动态包，分别生成修改后的包。
4. 服务端主包和动态包自动备份后替换；替换后会核对服务器文件 SHA-256。
5. 修改后的客户端包会下载到本机，需要手动替换游戏目录中的客户端 `mb.dpk`。
6. 重启游戏服务端和客户端后验证。工具不会自动重启服务端；服务端进程运行期间虽然会写入包文件，但进程已加载的配置通常需要重启后才会重新读取。

服务器备份文件名带有 `.bak.summon.<时间戳>` 后缀。客户端包由工具下载，不会自动覆盖本机文件，替换前应自行保留原客户端包。

## 数据保存

最近一次的界面选择保存在运行目录 `data/summon_skill_config.json`，用于下次打开页面时恢复召唤物和召唤物技能冷却配置。该文件属于运行数据，不纳入 Git；旧记录中的召唤技能名称和冷却值会在下次应用时分别被“召唤伙伴”和 10 秒覆盖。

## 已知边界与排查提示

- 召唤物技能窗口由 `summon/summon_skill.txt` 和 `summon/summon_skill_index.txt` 决定；自动技能选择还受外形对应的 `cha_skill_choose.txt` 配置影响。应用时会重写该外形行，若多个角色共用同一外形，配置会影响这些共用者。
- 怪物和捕快的原生 AI 行包含技能条件与权重；当前自选流程会覆盖这些配置。游戏实测可能表现为只用普通攻击，或不再按怪物原有 AI 释放技能。复制原 AI 并让召唤物按原逻辑自动施法还未实现。
- NPC 技能数据按技能 ID 修改。多个召唤物若共用相同技能 ID，冷却设置也会共用，应用窗口会提示。
- 当前功能只配置召唤外形、技能行为和技能栏，不主动写入属性继承规则。仙友的游戏内最终属性可能由运行时规则或其他配置共同决定，尚不能仅凭 `cha_fight.txt` 静态行准确推算。
- 新技能的学习和技能栏记录写入 DPK；实际能否在游戏中学习，还取决于客户端使用了下载后的包、服务端包已替换，以及游戏内技能导师/技能配置是否重新加载。
- 代码通过复制六合签触发记录来继承召唤行为；召唤持续时间来自该模板的触发配置，技能说明文字也写入“持续十分钟”。当前实现没有单独设置一个数值型的“600 秒存在时间”字段。
- 代码没有显式清空一个名为“非战斗状态不可使用”的独立字段。当前版本改为使用六合签触发模板，避免继承巨甲遁原触发；若游戏内仍提示战斗状态限制，应检查六合签触发模板自身的条件字段并在实机验证。
- 若出现召唤出错误外形、旧召唤物或冷却互相影响，优先核对客户端和服务器是否使用同一轮生成的包，并确认新技能 ID `3126`、触发 ID `302247` 和动作 ID `30422` 至 `30424` 没有被其他配置覆盖。

## 回滚

服务端主包和动态包可用本次操作生成的 `.bak.summon.<时间戳>` 备份恢复。客户端需恢复替换前自行保存的原始 `mb.dpk`。恢复后重启服务端和客户端。
