# 武器最大生命值百分比伤害实现文档

目标：装备武器 60074 时，每次有效命中额外对目标应用 5% 最大生命效果；适用怪物和玩家。

## 百分比伤害的工作原理

### 计算基准

目前配置的是**目标最大生命值的 5%**，不是目标当前剩余生命值的 5%。例如目标最大生命值为 100,000 时，状态配置对应的基础生命变化量为 5,000；即使目标当前只剩 20,000，计算基准仍是 100,000。最终扣血、死亡处理、免疫及数值取整等行为仍由游戏状态系统处理，不能仅凭这个公式断定所有目标都会恰好扣除 5,000。

### 一次命中的处理过程

1. 攻击进入服务端 `CServerCha::BeHit` 中已挂接的两个伤害调用点之一，钩子先执行原本的 `DealDamage`。
2. 原伤害调用返回值大于 0，并且攻击者是玩家时，读取玩家当前装备的武器槽 `1810`。未装备武器或不是玩家的攻击者不会通过此判断。
3. 根据武器实例的物品 ID 读取物品定义，检查五个装备属性槽是否包含自定义词条 ID `65000`。这个判断读取的是武器定义，多个武器可以共用该标记。
4. 满足条件后，钩子把状态 `16890` 加入目标的待添加状态列表，并把攻击者 ID 传给状态系统作为来源。状态的子状态配置为按目标最大生命值减少 5%；额外效果通过状态系统执行，不是直接改写原始 `DealDamage` 的伤害数值。

原始伤害和附加状态是先后处理的两个步骤。状态进入待添加列表不等于已经确认扣血成功；目标是否存活、状态是否被免疫或覆盖、何时结算等仍需在实际场景中验证。当前没有额外的防重复触发控制，也不能保证所有攻击类型都经过这两个挂钩调用点。

### 词条与文字的分工

- 武器 `60074` 的一个装备属性槽填入 `65000`，取代原来的生命 `+11625` 词条。`65000` 在 `item/item_trait.txt` 中是零数值标记，负责让自定义钩子识别，不负责计算 5%。
- 5% 的配置来自状态 `16890` 的子状态；修改武器说明文字不会改变伤害比例。
- 客户端物品表的文字介绍 ID `21550` 指向 `etc/text.txt` 中的橙色“雾之锋”说明。它只负责显示，必须替换客户端包才能看到更新。
- 服务端钩子由 `scripts/native/weapon_percent_trait_test.c` 提供，目前安装在服务端进程内，重启后需要重新安装；仅有词条和说明不代表伤害效果仍然生效。

### 当前验证范围

先前按武器 ID 直接判断的版本已由用户在游戏内反馈符合预期；后来改成读取词条 `65000` 的版本已检查代码、部署和调用点，但尚未获得完整的游戏内验证。怪物和玩家均是设计目标，具体攻击方式、目标免疫、多段攻击与重复触发等不能仅根据此前反馈认定全部通过。九星技能上原来的测试修改已撤销。

## 伤害回血测试更新

当前测试服运行模块改为 `scripts/native/weapon_percent_lifesteal_test.c`：保留 `65000` 的原有效果，另对武器 `60074` 按 `DealDamage` 正返回值的 5% 给攻击者回血。该段为 2026-11-01 历史测试，现行版本见下方“伤害比例吸血”。运行时修改在服务端重启后消失。

## 现有依据

- 主包和动态包的 60074 是普通武器，5 个附加属性槽已使用；`item/item_trait.txt` 是战斗数值属性配置，没有找到可直接绑定命中状态的字段。
- 传奇装备 `CEquipFeatureMngBase::SetLegendEquipData` 会查表 1570、装备实例数据和特性组；不能仅添加普通道具表行就证明所有攻击会触发。
- 当前服务端 `TTYGZS_d.so` SHA-256：`9a19e9c8deaefeb8ba35d61f10ccc6f32d166ef2ee2aedf1f3ecf06cfa7109bb`。版本不同不得使用本文地址。
- `CServerCha::BeHit` 中有两个调用 `CServerCha::DealDamage` 的调用点：`0x926bf8`、`0x926c2e`。`DealDamage` 同时也被状态周期伤害等路径调用，直接对其全局挂钩无法自动区分武器命中与状态伤害。
- 符号 `CCha::GetChaDataMng()` 返回对象偏移 `0x28` 的数据管理器；`CObjDataMngBase::IsPlayer()` 可以判断玩家；`CPlayerDataMngBase::GetItemMngBase()` 获取物品管理器。
- 服务端 DWARF 常量 `ItemAutoID_Weapon` 为 **1810（0x712）**。不可误用附近其他装备槽位。物品结构的具体布局和调用约定还需在运行版本中进一步核对。
- 之前已在九星上实际测试状态 `16890`，其子状态配置为目标最大生命值的 `-5%`；该九星修改后来已移除。

## 伤害比例吸血



当前测试武器为破败王者之刃，物品 ID `60075`。装备定义中的词条 `65000` 是自定义效果标记；其显示名称为“造成伤害的5%转化为生命值”。最大生命值伤害仍通过状态 `16890` 执行，武器下方另有对应说明。

在已接入的普通命中路径中，普通伤害得到正的 `DealDamage` 返回值后，回血基数为 `返回值 / 20`；若目标状态管理器存在，再加上 `(目标最大生命值 / 20) / 20`。各次除法均为整数除法、向下取整，后者约为目标最大生命值的 0.25%。这是用户选择的估算方案，不等待状态 `16890` 的实际扣血；目标免疫、附加伤害未生效或剩余生命不足时，估算部分仍可能回血。最终恢复量受攻击者生命上限约束。

回血调用 `CServerCha::ChgHP` 后，以返回的实际恢复量发送参考导引术治疗分支的通知；实际恢复量为零时不发送。用户已在游戏中确认回血数值显示成功；免疫、致死、多段攻击及接近满血等边界尚未逐项验证。

测试源码为 [summon_sync_damage_lifesteal_display_test.c](../data/weapon_effect_restore/sources/summon_sync_damage_lifesteal_display_test.c)。普通线和交易线已安装模块 `refresh-cf9c31b71d8f3c9305bc1a9a.so`，调用点回读通过；自动恢复服务已更新并运行，但尚未再次实测重启恢复。早期测试的武器 ID、计算方式和部署状态不代表当前版本。

目标：角色攻击造成伤害后，按照该次伤害的 5% 恢复攻击者生命。例如本次计入吸血的伤害为 10,000 时，计算出的回血量为 500；生命上限、取整和其他治疗规则还要由服务端处理。

## 现有吸取生命属性

服务端主包 `etc/atb_fight.txt` 将战斗属性 `33` 定义为“吸取生命”，支持绝对值和百分比；`item/item_trait.txt` 中有 `2835\t33\t150\t0\t\t吸取生命+150` 等词条。这些记录的名称与参数本身不足以证明是按伤害的百分比回血。

对与当前运行版本一致的 `TTYGZS_d.so`（SHA-256 `9a19e9c8deaefeb8ba35d61f10ccc6f32d166ef2ee2aedf1f3ecf06cfa7109bb`）静态分析 `CServerCha::BeHit` 可见：代码读取攻击者的战斗属性 `33` 的绝对值和百分比值；绝对值可直接作为恢复量，百分比值大于 0 时，代码用它乘以攻击者属性 ID `12`，再调用攻击者的 `CServerCha::ChgHP`。`etc/atb_fight.txt` 将属性 ID `12` 标注为生命值上限。因此这条百分比分支使用的是攻击者的最大生命值，不是本次伤害值。代码还有技能数据第 51 列参与的另一分支，会按技能参数重新计算，具体适用条件和单位尚待确认。

以上为反编译静态观察，未进行游戏内验证。该结论只覆盖检查到的 `BeHit` 分支，不排除其他系统另有伤害比例吸血实现。

## 名称为“吸血40%”的状态

`skill/state_data.txt` 的子状态 `38489` 名为“吸血40%”，其“是否百分比”为 `1`、“当前生命”为 `40`，对应状态组 `38489`。表头显示这是对生命变量的百分比变化；名称里的“吸血40%”不能单独证明它基于本次伤害。根据已有状态系统分析，它应按受状态对象的生命上限计算，具体受益对象和技能调用链还需核对。

## 按伤害回血的可行路径

现有自定义武器效果已经在 `CServerCha::BeHit` 的两个 `DealDamage` 调用点安装运行时钩子。钩子先调用原 `DealDamage`，取得其返回值，再读取攻击者和武器。这为在同一位置加入“回血 = 返回伤害 × 比例”的逻辑提供了可复用的入口；服务端也有 `CServerCha::ChgHP(int)` 可改变角色生命。

`DealDamage` 反编译结果显示：它对输入伤害经过吸收等处理后，调用目标 `ChgHP(-伤害)`，并返回处理后的伤害变量。该返回值是有依据的候选计算基数，但尚未证明它在目标剩余生命不足、护盾、免疫、死亡或额外伤害等情况下始终等于目标实际减少的生命值。要严格按实际扣除量吸血，需进一步验证或读取扣血前后生命值，并处理结算期间其他生命变化。

建议后续实现时为吸血单独配置比例和标记：先确认命中及攻击者有效，选定伤害基数，按比例计算回血并由攻击者 `ChgHP` 处理；不把现有 `65000` 最大生命百分比伤害标记直接当成吸血标记。现有钩子仅覆盖已确认的两个调用点，并只在进程内生效；服务端重启后需重新加载。后续测试版已实现并部署，现行版本见本节开头。
