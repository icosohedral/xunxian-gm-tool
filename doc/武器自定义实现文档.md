# 武器自定义实现文档

本文记录工作台「物品管理 → 装备新增」的设计依据与实现流程。页面支持武器模板筛选、草稿编辑、跨包 ID 冲突校验、写包部署和客户端包下载；发放角色仍使用现有物品发放功能。

## 第一步：读取和筛选武器模板（已核实）

### 数据来源

以当前客户端工作包 `data/client_mb_work.dpk` 为筛选来源，读取以下三个资源：

- `item/item_list.txt`
- `item/item_list2.txt`
- `item/item_list3.txt`

三张表均为制表符分隔文本，首行是列名。`item/item_type.txt` 将物品类 `100` 定义为「武器」，因此初筛条件是「物品类」字段等于 `100`，不能只根据物品名称猜测。每条记录需保留原表路径，后续复制模板时才能在正确的表中生成新行。

### 当前包的筛选结果

统计日期：2026-10-26。客户端工作包与当前服务端主包的武器数量一致。

| 资源 | 物品类为 `100` 的记录数 |
| --- | ---: |
| `item/item_list.txt` | 549 |
| `item/item_list2.txt` | 3,591 |
| `item/item_list3.txt` | 219 |
| **合计** | **4,359** |

这 4,359 条记录的物品 ID 均不重复，名称、道具图片和模型 ID 字段均非空。数量是当前包的快照，实际界面应从已配置的包实时统计。物品类 `100` 中也有「一大叠空白符纸」「专攻武器-测试」等特殊条目；初版可如实展示，后续再确定是否增加测试物品过滤规则。

### 职业筛选

物品表第 10 列（从 1 开始计数）为「职业限制」，代码中下标为 `9`。当前武器的取值与数量如下：

| 字段值 | 对应职业大类 | 数量 | 包内示例 |
| --- | --- | ---: | --- |
| `1` | 游侠 | 1,081 | 短剑、长剑 |
| `2` | 力士 | 1,065 | 铁槌、短斧 |
| `3` | 符咒师 | 1,081 | 木剑、驱邪草麈 |
| `4` | 法师 | 1,081 | 木杖、硬木杖 |
| 空 | 未填写职业限制 | 51 | 普通短剑、天雷神剑等 |

这一列只有四个职业大类，没有直接区分驭剑与奇门、金刚与罗刹等细分职业。大类名称是根据包内武器样本及现有项目的职业分组核对的。界面可提供「全部／游侠／力士／符咒师／法师／未限制」筛选，同时支持按名称和物品 ID 搜索。选择模板后，应展示其原始职业限制值，避免把空值自动解释为某个职业。

### 实现要点

1. 使用已配置的客户端工作包；读取时只解出上述资源，不必完整解包。
2. 按列名或经校验的列位置读取物品 ID、名称、物品类、职业限制、道具图片和模型 ID；跳过表头与无效行。
3. 仅收录物品类 `100`，以物品 ID 为唯一键，保留来源表路径和完整原始字段，供后续复制模板。
4. 职业筛选依据原始字段值，不从武器名称推断职业；显示统计数量时以当前读取的包为准。

## 第二步：编辑草稿与模拟 ID（已实现）

「装备新增」左侧从共享客户端工作包筛出武器，可按职业大类和名称／ID 检索；列表每次最多显示 60 条，并显示匹配总数。选择模板后，中间草稿卡片载入完整的 55 列记录，允许调整名称、职业、等级、伤害、防御及四维属性。图标预览和道具图片名与伤害力、防御力同排；点击图标弹出图片选择窗口。候选图片须同时存在于 `logos/icons/wq`，并在包内武器记录中有对应模型 ID；选中图片后，将其名称写入道具图片字段，并按表内顺序反查第一个模型 ID 自动写入草稿。新装备草稿固定将「物品品质」设为 `10`、「耐久」设为 `300`，页面不显示这两项。右侧「属性词条」卡片常驻，使用与模板列表一致的搜索区、表格和匹配总数；从 `item/item_trait.txt` 按名称或 ID 搜索，点击条目直接追加到草稿，最多五条。草稿只显示已选词条，按可用宽度自动换行，一行可放多条；点击删除按钮可移除，剩余词条自动前移。词条名称靠左、末尾属性数值靠右，列表不显示 ID；草稿内部仍保存对应 ID。其他未开放的列沿用模板值。

页面候选 ID 从客户端工作包及服务端包缓存的物品 ID 中计算，仅供预览，不会预留。点击「生成并同步」时，后端先通过远端 SHA-256 检查主包和动态包缓存的新鲜度；缓存过期时重新下载，再对客户端工作包、服务端主包和动态包的三张物品表做联合冲突检查，分配当前最大 ID 加一，并限制不超过 `65535`。随后校验名称、武器类型、固定品质与耐久、词条 ID、道具图标及其首个模型 ID。

写包时按物品表表头把 55 列客户端记录转换为各包格式：客户端及服务端主包为 55 列，动态包为 52 列；动态包缺少的字段不会写入，别名字段按表头对应。每个包都复制模板记录并追加新行，使用 DPK 块链扩展写入。写入后回读新行，验证列数和所有共有字段。

部署阶段将主包和动态包上传到服务器临时位置，先备份原包，再原子替换；服务端文件 SHA-256 与本地产物不一致时返回失败并保留备份。成功后更新共享服务器缓存和客户端工作包，提供新的客户端 `mb.dpk` 下载，并自动请求重启服务端。重启可能断开在线玩家；下载的客户端包需替换到游戏目录。

后端读取逻辑在 `scripts/weapon_drafts.py`，写入逻辑在 `scripts/weapon_custom.py`；工作台接口为 `GET /api/weapon_templates`、`GET /api/weapon_traits` 和 `POST /api/weapon/apply`。客户端包下载接口为 `GET /api/weapons/download`。当前包中的词条 ID `4357` 为「承受伤害降低30%」，`2835` 为「吸取生命+150」，均已通过查询验证。当前实测客户端和服务端主包为 55 列，动态包为 52 列；三种格式已通过本地隔离写入、回读核对。真实服务器写入和游戏内效果需在工作台确认生成后验证。

## 后续待核实

- 游戏内检查新武器穿戴效果、属性计算和装备词条效果；这些效果需以目标客户端与服务端版本实测为准。
- 新武器通过现有发放物品目录和发放功能交给测试角色；记录是否还需刷新目录或重启工作台。
