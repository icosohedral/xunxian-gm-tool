# 修道者召唤符（12538）使用原理

本文根据当前服务端包、脚本及程序静态分析整理，尚未通过游戏内测试确认全部行为。调查时，本机主包、动态包和脚本包与服务器对应文件的 SHA-256 一致。

## 道具与配置

| 项目 | 配置 |
|---|---|
| 道具 | `12538`：修道者召唤符-60级 |
| 主包道具表 | `item/item_list.txt`，使用属性为 `11028` |
| 使用属性 | `item/item_use.txt` 中 `11028`，效果类型 `3`，脚本编号 `1427`，后续参数为 `60`、`70` |
| 脚本注册 | `server/script_func_reg.txt` 中 `1427` 对应 `i_summonnpc` 的 `Item_Use` |
| 脚本 | `script.dpk` 内 `specialuse_script/i_summonnpc.c` |
| 召唤符配置 | 表 `1002`，主包内 `server/script_excel/i_summonnpc.txt` |
| 召唤行为配置 | 表 `306`，`pet/summon_type.txt` 中类型 `39` |

## 使用流程

1. 使用道具后调用 `i_summonnpc`。脚本检查场景和玩家对象，并按道具 ID 在表 1002 查找配置。
2. 脚本取 `G_Rand(100)`，与本行的概率值 `10` 比较，小于 `10` 时选择特殊 NPC，否则选择普通 NPC。若随机函数均匀分布，分别为 10% 和 90%。
3. 脚本在玩家当前位置调用 `Summon_Add`，召唤类型为 `39`。创建失败时直接返回；成功时设置 NPC 的 `SetOnCourse(true)` 和玩家的道具使用成功临时标记。

| 结果 | 概率 | NPC ID | 角色表名称 | 角色表等级 | 战斗能力 ID |
|---|---:|---:|---|---:|---:|
| 普通 | 90% | 5653 | 落魄修道者 | 60 | 3154 |
| 特殊 | 10% | 5654 | 落魄修道者 | 70 | 3182 |

脚本并不根据使用属性中 `60`、`70` 直接设置等级；它按道具 ID 查询表 1002，使用其中的 NPC ID。等级和战斗能力 ID 来自 `object/cha_list.txt` 中相应 NPC 行。

## 行为与属性

召唤类型 39 的配置包含攻击主人的目标、跟随主人、显示主人名、最多一个召唤物等；主包还配置了与主人共仇恨。实际行为仍可能受到游戏引擎和 NPC AI 影响。

从服务端创建逻辑看，修道者按 NPC ID 创建，主要使用自身 NPC 配置。已检查的 `Summon_AddOne` 会为特定召唤类型调用 `InitSummonStraw` 主人属性初始化逻辑，而类型 39 不在该分支范围内。因此现有证据支持它的基础等级和战斗能力由 NPC 自身配置提供，而非直接继承玩家属性。尚未逐项追完所有属性计算和状态加成，不能排除技能或增益产生间接影响。

## 持续时间与限制

- 表 1002 的「时间」列为 `10`，但脚本标注该列未使用，也没有读取它，不能据此判断持续时间。
- 表 306 的召唤类型 39「存在时间」为 `600`；服务端会将其传给 `SetNaturalLife`。该值的时间单位和实际消失条件尚未完全验证。
- 使用属性列出了禁止使用的场景 ID：`456、458、461–476、486–501、546、566、567`。具体名称需对照实际场景表。
- 脚本自身不直接删除召唤符，而是设置道具使用成功的临时标记。最终的消耗时机及创建失败时是否消耗，需继续追踪引擎逻辑或进行游戏内验证。

以上概率和配置以调查时的服务端包为准；修改包或存在运行时覆盖文件后应重新核对。
