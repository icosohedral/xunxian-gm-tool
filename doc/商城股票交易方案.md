# 商城「股票交易」功能方案

## 已确定的需求

- 在商城顶部新增与「仙玉商城」「积分商城」并列的「股票交易」页。
- 使用游戏内流通金，先提供 3 只虚拟股票。
- 价格由服务端按固定时间间隔随机波动；只作游戏娱乐，不接入现实行情。

## 已核对的客户端结构

- 当前客户端 `resource.dpk` 的 `gui/group/group_mgr/group_mgr.xml` 加载 `/group/shop/shop.xml`。
- `gui/group/shop/shop.xml` 的 `group_top` 是顶部标签容器，页面内容在其下方的配置面板中。
- `gui/group/shop/shop.cc` 的 `shop_btn_to_group_ptr` 将按钮映射到页面；`on_group_click` / `on_group_rise` 负责显示切换。商城打开时默认点选仙玉商城。
- `gui/group/shop/shop_c.xml` 注册 `shop.cc` 为 `ui_shop` 脚本。
- 现有顶部有公告、积分、仙玉、购物车、交易、拍卖行、收购行，右侧有搜索框。新增按钮时应重新分配宽度并在游戏内检查低分辨率布局。
- 包内另有 `gui/group/shop2/`，但当前 `group_mgr.xml` 加载的是 `shop/`；快捷栏脚本可按 `ug_shop_switch` 选择 `shop2`，实施前需核对目标环境的开关值。

## 建议的第一版体验

页面列出股票名称、当前单价、上次涨跌、持有数量、持仓市值；选择股票后显示买入和卖出操作、数量与预计金额，并展示流通金余额。每笔买卖返回明确结果及最新余额、持仓。

建议默认参数（实施前可调整）：每 5 分钟变价一次，每次独立随机波动不超过 3%；初始价格分别为 1、3、5 砖/股；单笔买卖 1、10 或 100 股；不收手续费。价格不得低于 0.1 砖。所有价格和金额均以铜为整数保存，1 砖 = 1,000,000 铜。

## 实现边界

1. **客户端 UI**：在 `shop.xml` 添加标签和 `stock.xml` 页面；在 `shop.cc` 注册按钮映射、页面显示及隐藏；在客户端文本资源中加入中文标签和提示。页面复用现有商城按钮、列表与金额样式。
2. **服务端状态**：服务端保存三只股票的价格、更新时间和每个玩家的持仓。重启后恢复价格及持仓，不能只存在客户端变量或临时 NPC 标志里。
3. **交易请求**：客户端买卖请求必须有明确的服务端入口。服务端使用玩家身份、股票 ID、方向和数量重新校验价格、余额、持仓及金额上限，然后执行扣款/入账与持仓变更；处理重复请求，记录交易日志。客户端显示服务端回执，不自行结算。
4. **价格更新**：仅服务端的定时任务变价；玩家打开页面时获取快照，定时刷新。结算使用服务端收到请求时锁定的价格，回执包含成交价。
5. **金额上限**：现有角色流通金接口使用有符号 32 位整数，买入总额先用除法判断再相乘，卖出入账先用上限减成交额再比较余额，避免溢出。
