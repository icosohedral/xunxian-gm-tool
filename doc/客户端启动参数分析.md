# 客户端启动参数分析

分析对象：`release/tty3d.exe`，SHA-256 `59e50674a8f57f99c3ec828fe9989a6949f47b957d630a9b3c227a780c25e4ff`，与《客户端资源读取逻辑分析》是同一版本。工具是 Ghidra 12.1.4。下面的地址都是这个版本 PE 的虚拟地址，函数名是 Ghidra 自动生成的，不是源码里的名字。登录窗口脚本取自 `resource.dpk` 里的 `gui/section/user_entry/user_entry.cc`。

结论：客户端支持用 `-q` 参数传入账号和密码。登录窗口第一次显示时，会自动填入这两个值并登录。[`launcher/`](../launcher/) 里的寻仙登录器就是靠这个参数实现自动登录的。

## 用法

```bat
tty3d.exe -g "IP:端口,服务器名" -q "0:账号:0:密码"
```

- 原启动脚本用 `-g` 指定服务器地址。
- `-q` 的值用冒号分成 4 段，第 2 段是账号，第 4 段是密码；第 1、3 段在不走腾讯 TCLS 时没用到，填 0 即可。
- 账号和密码里不能出现分隔符 `:`。

## 参数解析

参数解析在 `0x00408f30`，由启动流程 `0x00409c60` 在读完 `client2_cfg.txt` 之后调用。处理过程：

1. `0x005c1b90` 把命令行拆成参数数组。
2. 循环每次前进 2 个元素，把当前元素当作选项名（`_stricmp`，不区分大小写），把下一个元素当作它的值。所以每个选项后面都必须跟一个值；如果漏掉一个值，后面的参数会全部错位。
3. 值由 `0x005bf2d0(格式, 值, 分隔符, 输出...)` 按分隔符拆成若干段，写入函数内的局部缓冲区。格式串里 `s` 的个数就是段数。

| 选项 | 格式 / 分隔符 | 段数 | 写到哪里（局部偏移，以循环内 ESP 为基准） | 用途 |
|---|---|---|---|---|
| `-q` | `ssss` / `:` | 4 | 0xc0、0x160、0x3e8、0x2440 | 第 2 段 = agent name（账号），第 4 段 = agent pwd（密码） |
| `-r` | `ss` / `:` | 2 | 0xc0、0xd18 | 第 2 段 = agent code |
| `-i` | `s` | 1 | 0x1730 | agent info |
| `-k` | `s` | 1 | 0x780 | agent 对象第 5 个字段（+0x100ac），用途未追踪 |
| `-g` | `ss` / `,` | 2 | 0xe0、0x1e0 | 第 1 段写入全局字符串 `0x00797dfc`，即服务器地址，覆盖 `client2_cfg.txt` 里的地址；第 2 段（服务器名）的用途未追踪 |
| `-film` | 原值 | 1 | `this+0x3c`，并置 `this+0x38 = 1` | 疑似播放录像，未验证 |
| `-script` | 原值 | 1 | 值为 `precompile` 时置 `this+0x5c = 1` | 置位后，启动流程在 BuildScript 之后会额外调用 `0x00538c90`、`0x00549dd0`，疑似预编译脚本，未验证 |

- `-q` 的第 1 段和 `-r` 的第 1 段写进同一个缓冲区（0xc0）。
- `-q` 的第 3 段（0x3e8）在解析之后的用途没有追踪到。

## 账号密码怎么到达登录窗口

1. 解析完成后，客户端尝试加载腾讯登录代理 `..\TCLS\Tenio\TenProxy.dll`。本客户端没有这个文件，日志记录 `Create TCLS proxy failed`，随后跳到 `0x00409b13`。TCLS 成功时的分支（读取 QQ 号、登录密钥等）没有分析。
2. `0x00409b13` 检查账号缓冲区（0x160）是否为空。不为空时，调用 `0x00569b80`，把 5 个缓冲区写进全局网络对象 `0x00787de8`（CTTYNet）的 5 个 `std::string`：

   | 偏移 | 来源 | 脚本接口 |
   |---|---|---|
   | +0x1003c | `-q` 第 2 段 | `getagentname()`，getter 在 `0x00401460` |
   | +0x10058 | `-q` 第 4 段 | `getagentpwd()`，getter 在 `0x00418e80` |
   | +0x10074 | `-r` 第 2 段 | `getagentcode()` |
   | +0x10090 | `-i` | `getagentinfo()` |
   | +0x100ac | `-k` | 没找到对应的脚本接口 |

3. 登录窗口脚本 `user_entry.cc` 第一次显示登录界面时（`g_first_show`），如果 `getagentname()` 和 `getagentpwd()` 都不为空，就设 `g_auto_login = true`，切到自动登录面板，再调用 `exec_auto_login()`：
   - 把账号和密码填进输入框；
   - 把 `getagentcode()` 存到 `g_code`；
   - 记一行日志 `auto login :<账号>`；
   - 发起连接。
4. 连接成功后，`pNet->login(账号, 密码, 角色密码, g_code, getagentinfo(), ...)` 发出登录请求，和手动输入走的是同一个接口。

另外，`0x00409c60` 在 `DAT_007878d0 < 1` 且 agent name 为空时，会记录 `Set agent name failed, can not run the program directly` 并退出，也就是要求必须通过登录器启动。当前配置下直接带 `-g` 启动能正常进游戏，说明这个检查没有触发；`DAT_007878d0` 的来源没有追踪。

## 运行验证

2026-11-13 在 CrossOver 里实测，用的是假账号：

- 命令行带 `-q "0:clauderetest:0:wrong&pass!1"` 启动。进程命令行原样收到了参数，包括 `&` 和 `!`。
- 客户端日志依次记录 `..\TCLS\Tenio\TenProxy.dll` 和 `Create TCLS proxy failed`，与上面的静态分析一致。
- UI 日志记录 `auto login :clauderetest`，说明自动登录流程已经触发。
- 测试时服务器 3100 端口连不上，日志为 `ui_api_connect_rst : -1`，所以服务器对账号的校验结果没有验证到。

## 限制与注意

- 密码以明文出现在进程命令行里，同一台机器上用 `ps` 就能看到。
- 角色密码（`cha_password`）不经过这些参数。设了角色密码的账号，自动登录后仍会弹出输入框。
- 各缓冲区的长度上限和 `0x005bf2d0` 是否检查越界，都没有核实，账号和密码不要过长。
- 账号含非 ASCII 字符时，取决于 wine 容器的 ANSI 代码页，没有测试。
