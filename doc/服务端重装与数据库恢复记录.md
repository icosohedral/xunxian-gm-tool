# 服务端重装与数据库恢复记录

## 2026-11-02 操作记录

本次在原服务器重装 `/opt/xxserver`，不是原地覆盖运行中的安装：

1. 通过当前数据库连接导出五个非系统库（四个 `xunxian_*` 业务库及 `test`），包含存储过程、事件和触发器。使用 InnoDB 一致性快照，生成的本地备份为 [xunxian-20261102-223309.sql.gz](../data/database_backups/xunxian-20261102-223309.sql.gz)。压缩包与传输前的 SHA-256 一致，gzip 和库清单检查通过，未做独立恢复演练。
2. 确认没有在线角色后，使用 `sudo /opt/xxserver/stop.sh --clients-exited` 正常关闭游戏和数据库。安装包位于 `/home/ubuntu/xxsrv.tar.gz`，解压安装目录为 `/home/ubuntu/xxsrv/xxserver-snapshot`，其清单标记 `FINAL_SNAPSHOT`。安装器面向空的 `/opt/xxserver`，使用该服务器已配置的网卡地址 `10.0.0.4` 安装。旧目录先暂时移走，安装及启动成功后按用户要求删除。
3. 安装器先恢复了安装包自带的旧数据库。随后再次正常停服，将上述本地数据库备份传到服务端并校验哈希，在只运行新数据库的状态下删除对应目标库并导入备份。导入返回成功；检查了四个业务库的表数量、角色“小统领”存在，以及在线锁和 DBI 临时连接表为空。
4. 安装器重新生成数据库凭据。为恢复工作台连接，给本机 TCP 的数据库管理员账户配置新凭据并同步工作台连接配置；工作台数据库查询测试成功。原 `gmtool-persistent-effects.service` 因依赖旧安装目录中的自定义运行模块而停用，重装不会自动恢复这些效果。
5. 启动后普通线、交易线和数据库均报告就绪，客户端成功登录。有关公网登录门票地址的修复与实际验证，见 [添加游戏登录 IP 白名单](添加游戏登录IP白名单.md#公网登录门票地址排查2026-11-02)。

安装包是 10 月的服务端快照，不包含后来添加的自定义物品定义（例如 60074–60078），但导入的数据库可能仍有对应物品实例；数据库恢复不等于恢复之后修改过的服务端 DPK、运行模块和配置。客户端包也不会由该安装器替换。重装前后需分别核对数据库、服务端包、客户端包及运行模块的版本。

## 再次执行时

操作前先让玩家正常退出，并做好最新数据库和需要保留的服务端文件备份。检查安装包、目标路径、数据库备份和新服务器地址；安装器会拒绝覆盖现有 `/opt/xxserver`。数据库导入会替换目标业务库的数据，应确认备份和目标环境，导入失败时停止后续启动并保留备份。安装完成或状态就绪不等于客户端验收完成，需实际验证登录、角色和所需游戏功能。
