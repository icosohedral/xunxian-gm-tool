# 怪物击杀仙玉奖励待实现方案

状态：尚未实现，也未进行游戏内验证。目标是指定怪物死亡后向最先攻击者所属账号发放配置数量的仙玉，不生成掉落物，并保留原有死亡和奖励流程。

服务端 `CServerChaNPC::SetDead(int)` 的死亡处理中有 `GetFirstAttackPlayer()` 和 `GetLastAttackPlayer()` 调用；前者是首攻归属的候选接口，返回对象的有效期以及宠物、组队、持续伤害和离线场景的归属仍需验证。`CPlayerDataMngS::AddPayBackPoint(int, int, int, bool)` 是候选点券接口，参数、单位、代理回执和实际入账均需验证。以上线索来自特定版本的静态分析，不可直接套用到其他版本。

实施时应先只读追踪有效死亡分支并确认怪物 ID 与首攻玩家，再通过仅记录事件的钩子验证归属和重复触发，之后小额验证点券接口并接入奖励配置。同一怪物实例单次死亡需防止重复发奖；还需设计失败记录、补发、版本校验和回滚。没有可靠回执或持久化事件时，不能保证失败后自动补发或不重复。
