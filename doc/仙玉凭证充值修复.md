# 仙玉凭证充值修复

## 问题

使用仙玉凭证后道具被消耗，但账号仙玉余额没有增加。以仙玉凭证（10000仙玉，物品 ID 49983）为例，道具使用配置调用效果 98，向点券服务发送增加 10000 点券的请求；100000 仙玉凭证也使用同一类效果。

服务端点券代理将负数金额请求一律视为购买退款，要求找到对应的原扣款记录。凭证充值没有原扣款，因此被拒绝，余额没有变化。

## 修复方式

修改服务端 `/opt/xxserver/bin/transactions.py`：在原退款匹配逻辑之后，识别已观察到的凭证充值请求特征（`native_ext` 低 16 位为 `0x60`，请求末尾为 `43 00`），将负数金额作为充值处理，增加账号余额。

原有的退款匹配、余额上限和请求去重逻辑继续生效；不符合该特征且没有对应扣款的负数请求仍会被拒绝。请求特征来自实际记录，尚需在游戏内进一步验证不同凭证的行为。

仓库中的 `scripts/voucher_proxy_repair.py` 可对已核对的代理源码生成补丁；它不会自动部署到服务器，且会拒绝不匹配的源码版本。部署前服务器上保留了原文件备份，服务重启后新代理加载修复。

## 验证

使用真实数据库执行事务测试，验证了 10000 和 100000 点券请求、重复请求去重及普通负数请求拒绝。测试事务已回滚，没有改变账号余额。此前消耗的凭证未补发；仍需在游戏内使用凭证验证完整流程。
