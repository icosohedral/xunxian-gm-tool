# 商城股票交易

已部署到当前云服务器和本机客户端；游戏内端到端验收待玩家完成。详细原理与备份记录见 `doc/商城股票交易方案.md`。

## 玩法

- 商城顶部「股票交易」页，三只虚拟股票：腾讯科技、英伟达、Anthropic。
- 流通金即时买卖，每笔可选 1、10、100 股；每只股票最多持有 1000 股。
- 每五分钟报价改变一次，价格为初始价 1、3、5 砖的 ±3%，同一时段内固定。无需后台定时进程。
- 客户端调用服务端脚本 ID 2501；服务端计算价格、校验并结算。持仓在玩家 DWord 标志 200–202 中保存，报价及结果通过只发给该玩家的消息返回。

## 文件

- `r_stock_trade.c`：服务端交易脚本。
- `stock.xml`、`stock_ui.cc.inc`：客户端界面及事件代码。构建时写入包内原有的 `gui/group/shop/game_cangbao.xml` 和 `.cc`，商城主脚本通过 `#include` 引入后者。
- `build_resources.py`：从原始包提取并生成替换资源与文字表。
- `package_prototype.py`：生成经过回读校验的 DPK 原型。
- `build/`：生成物，不纳入版本库。

用户要求 `resource.dpk` 最多保留一份工作备份；更新前核对现有备份，安装并验证后清理重复构建副本，不累积多份备份。重新构建时使用当前适用的工作备份作为基线，并核对是否还有其他更新。

2026-11-07 首次安装曾使商城打不开：`resource.dpk` 增加文件和商城脚本块链时，包头块数未随文件增长更新，客户端日志报 `failed create stream '/group/shop/shop.cc'`。修正版复用两个原有闲置资源，所有替换项均在原有块链容量内；打包后核对条目数、根块位置和包头块数。`scripts/repack.py` 现也会同步更新包头块数并校验。

## 游戏内验收

1. 完全退出客户端后重新启动，进入商城，看顶部是否显示「股票交易」；点开后应收到三只股票报价、持仓和流通金余额。
2. 用测试角色选 1 股，买入一只股票。确认余额减少、持仓加一，价格按当时服务端报价结算。
3. 卖出 1 股，确认余额增加、持仓减一。重复点击卖出应显示持仓不足。
4. 登出重登，确认持仓仍在；跨普通线和交易线登录再检查一次。
5. 留在页面超过五分钟后点击「刷新报价」，确认新时段报价变化；同一时段反复刷新应保持一致。

若页面或交易有异常，先停止使用交易按钮，保留当时的角色名、时间、所选股票和股数，再检查对应线路日志。客户端原包、服务端原包均有 `.bak.stock-*` 备份。
